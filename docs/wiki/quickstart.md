# Quickstart

The CodeWiki system is built around a deterministic, three-stage workflow that transforms raw code into structured documentation without relying on stochastic AI models during the indexing phase. The process begins with the `codewiki/indexer` package, which orchestrates a multi-stage indexing workflow to populate a SQLite graph, ensuring reproducible data persistence through the foundational `codewiki/store` backend. This deterministic foundation allows the system to generate reliable evidence bundles, shifting the reliance on Large Language Models to later stages where they are used specifically for summarization rather than retrieval.

Once the code is indexed, the system leverages specialized packages to generate and assemble the final output. The `codewiki/generator` package acts as the central orchestrator for hierarchical summarization, isolating AI-dependent logic to maintain control over the generation process. These summaries are then processed by the `codewiki/writer` package, which implements a 'plan-then-fill' pipeline to replace stochastic context retrieval with deterministic, pre-computed evidence. Finally, the `codewiki/assembly` package combines these taxonomy definitions and runtime graph data to create static documentation, while the `codewiki/server` package provides a web interface via an asynchronous FastAPI backend to serve this content to users.

To ensure the reliability of this architecture, the `tests` package serves as the quality assurance backbone, verifying that all major components function correctly in both isolation and integration. For new contributors or users looking to understand the system, it is recommended to start with the Overview to grasp the high-level workflow, followed by the Indexer and Store packages to understand the data foundation. Next, review the Generator and Writer packages to see how summaries are created deterministically, and conclude with Assembly and Server to understand how the final documentation is rendered and served.

## How this wiki is maintained

Generated by `codewiki` (tree-sitter code graph → hash-gated local-LLM summaries → a plan-then-fill page writer with per-section Sources validation). Regenerate after structural changes with `codewiki update`; only pages whose underlying code changed are rewritten.
